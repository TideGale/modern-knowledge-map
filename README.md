# 现代知识地图

> 面向中文技术人的信息素养导航。

## 这不是什么

- **不是资源合集。** 那种东西 GitHub 上已经很多，多数三年后一半链接失效，也没人知道该信哪条。
- **不是推荐清单。** 推荐会过期，而清单不会告诉你什么时候过期。
- **不是教程。** 每篇讲的是判断方法，不是知识点本身。

## 这是什么

三个东西，按重要性排：

1. **判断方法。** 看到一个说法，怎么在五分钟内判断它值不值得信。
2. **有限入口。** 每个领域给 5 到 15 个一手来源，宁缺毋滥。
3. **维护机制。** 每个资源标核验日期，脚本定期查死链，失效的直接降级或删掉。

## 收录标准

四条硬标准，缺一条就不收：

| # | 标准 | 怎么判断 |
| --- | --- | --- |
| 1 | 一手或准一手 | 官方文档、法律原文、原始论文、标准文件、原作者维护的项目 |
| 2 | 开放获取 | 免费可读，没有注册墙和付费墙 |
| 3 | 持续维护 | 网站看是否还在更新，开源项目看近一年有无提交 |
| 4 | 可追溯 | 转载必须注明来源，二手内容必须能追回一手 |

**明确不收**：聚合导航站、盗版资源站、单一作者的观点合集、AI 生成的资源列表、需要注册才能看的"免费"资源。

## 三条判断原则

1. **能自动验证的才能信。** 代码跑一遍，链接点一次，数字核一遍。不能自动验证的，标明未核实。
2. **降级使用比升级安全。** 拿不准是几手，按低一级用。
3. **没有核验日期的推荐等于没有推荐。** 你不知道它是什么时候还有效。

## 核验机制

每个资源条目必须带五个字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | 官方名称，不用简称 |
| 地址 | 一级入口，不写深层链接 |
| 一句话 | 这个资源解决什么问题，不超过 25 字 |
| 等级 | A 官方原始 / B 开放教材 / C 社区线索 |
| 核验日期 | `YYYY-MM`，含义是"这个月我打开过，链接有效，范围没变" |

`scripts/check_links.py` 读 `data/resources.yml`，逐个请求，输出失效清单。建议每月跑一次。

## 谁能用

- **求职中的学生**：面试前查技术事实，别背二手说法。
- **写技术文档的人**：需要给别人一个可核验的引用。
- **被 AI 误导过的人**：想知道哪些场景必须查原文。

## 免责声明

医疗、法律、投资类内容**只做信息导航，不构成专业建议**。

涉及具体决策时，请查官方原文或咨询持证专业人士。这个仓库的价值在于告诉你"去哪里查"，不在于替你判断。

## 关于维护

这个项目由一个人维护，更新频率取决于实际使用。**不接受大批量资源提交**，只接受三类贡献：

1. 指出错误（事实错、链接失效、等级判断错）
2. 补充核验（你打开过某条资源，确认它还在）
3. 改进判断方法（有更好的验证流程）

详见 [CONTRIBUTING.md](CONTRIBUTING.md)。

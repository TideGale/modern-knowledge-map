# 01 信息素养

> 这一篇解决一个问题：**看到一个说法，怎么在五分钟内判断它值不值得信。**
>
> 核验日期：2026-11-25　｜　下一篇：[[02-AI工具与幻觉]]

## 一、先分清四种信息

绝大多数判断失误，不是不会分析，是把三手转述当成了一手来源。

| 类型 | 是什么 | 例子 | 怎么用 |
| --- | --- | --- | --- |
| 一手来源 | 当事人或原始数据的直接输出 | 法律原文、论文原始数据、官方 API 文档、企业财报、国家标准 | 当依据 |
| 二手解读 | 有人读过一手来源后的整理 | 教材、大学公开课、权威机构科普、维护良好的开源文档 | 当学习路径 |
| 三手转述 | 二次加工，通常带省略和改述 | 公众号文章、短视频讲解、AI 摘要、论坛回答 | 当线索，追回一手 |
| 噪音 | 目标是流量或成交 | 标题党、带货软文、编造的"研究表明"、AI 幻觉 | 忽略 |

**判断动作**：问一句"这句话的原始出处是哪"。答不出来，就降一级用。

举个真实例子。"某研究说每天喝咖啡超过三杯会缩短寿命"，这句话在三个地方出现，可能只有一个源头：一篇观察性研究，而观察性研究只能说明相关性，不能说明因果。等它转述到第四个地方，限定词全没了，就变成"咖啡缩短寿命"。

## 二、五个判断动作

### 1. 找原始出处

三问：谁说的，在哪说的，什么时候说的。

- 说"研究表明"，要能指出是哪篇、发在哪个期刊、哪一年
- 说"官方规定"，要能指向具体文号或条款
- 说"业内公认"，基本等于没有出处

### 2. 看作者的动机

| 信号 | 可能动机 |
| --- | --- |
| 文末卖课、卖咨询、拉社群 | 内容为转化服务，可能夸大问题 |
| 标题用"彻底搞懂""一篇就够了" | 追求传播，容易牺牲限定条件 |
| 全文没有一处可查证的引用 | 作者没做功课，或者不想让你查 |
| 同一作者长期深耕一个领域 | 相对可信，但仍要看具体证据 |

动机不代表观点错，但要求你多验一次。

### 3. 查知识的保质期

不同知识的过期速度差得很远，用同一套标准判断会出错。

| 领域 | 大概多久会过时 | 判断方式 |
| --- | --- | --- |
| 数学、物理基础 | 几十年不变 | 老教材可用 |
| 编程语言语法 | 三到五年 | 看官方文档当前版本 |
| 框架与工具链 | 一到两年 | 只看官方 changelog |
| 政策与法律 | 一年内可能修订 | 查现行有效版本 |
| 医学与营养 | 五到十年会被推翻一次 | 看最新综述，不看单一研究 |
| 市场与行业数据 | 一个季度 | 看数据发布方的最新口径 |

**具体动作**：看到一条信息，先问"这条知识多久会变"，再决定要不要查最新版。

### 4. 交叉验证

三个独立来源说同一件事，比一个权威来源说三遍更可靠。

"独立"的意思是：
- 不是同一个作者的多个平台账号
- 不是互相转载的关系
- 不是同一份数据的二次加工

可以查：官方通报、第三方核查机构、以及当事方的回应。三方都提到，基本站得住。

### 5. 看可证伪性

一个说法如果怎么都不会错，它就没有信息量。

| 不可证伪的说法 | 可证伪的版本 |
| --- | --- |
| 这个方法对大多数人都有效 | 这个方法的有效人群是 X，排除 Y |
| 长期来看一定会怎样 | 在 A 条件下会怎样，B 条件下不会 |
| 数据表明有明显提升 | 提升从 12% 到 18%，样本 200，时间三个月 |

看到第一种写法，先怀疑作者没做过测量。

## 三、AI 时代的特殊问题

AI 让信息生产的速度超过了核验的速度。三种幻觉最常见。

### 三种幻觉形态

**1. 编造引用**

给出看起来很像真的论文标题、作者、期刊、年份，但检索不到。这是最常见的形态，因为格式对了，可信度错觉就出来了。

验证方法：把标题原样粘进 Google Scholar 或 Semantic Scholar。搜不到就是编的。

**2. 张冠李戴**

把 A 的结论安到 B 头上，或者把某个特定条件下的结论说成普遍规律。

验证方法：要求给出原文段落。给不出来就是转述，按二手处理。

**3. 过度概括**

把一个个案说成趋势，把一个观察性研究说成因果。

验证方法：问样本量、问研究设计、问限定条件。

### 什么时候可以信 AI

| 场景 | 可以信 | 原因 |
| --- | --- | --- |
| 代码语法、API 用法 | 基本可以，但要跑一遍 | 错了编译器会告诉你 |
| 格式转换、文本润色 | 可以 | 不涉及事实判断 |
| 概念解释的初稿 | 参考，要对照教材 | 容易漏限定条件 |
| 具体数字、日期、人名 | **必须查原文** | 幻觉高发区 |
| 法律条款、医学建议、投资信息 | **必须查官方** | 错了有实际代价 |

一句话：**能自动验证的可以信，不能自动验证的必须查。**

## 四、资源的可靠性分级

| 等级 | 类型 | 具体例子 | 怎么用 |
| --- | --- | --- | --- |
| A | 官方与原始 | 法律法规数据库、国家标准全文公开系统、RFC、厂商官方文档、原始论文 | 当依据，可直接引用 |
| B | 开放教材与公开课 | MIT OCW、中国大学 MOOC、大学开放课程、维护良好的开源项目文档 | 当学习路径，系统过一遍 |
| C | 个人与社区 | 技术博客、Stack Overflow、知乎回答、GitHub issue | 当线索，找到后回 A 级验证 |
| D | 聚合与短视频 | 资源导航站、B 站讲解、AI 摘要、公众号合集 | 只当索引，不进正文引用 |

**核心纪律：正文里只引 A 和 B，C 只用来找线索，D 只用来发现方向。**

## 五、核验与时效

每个收录的资源都标核验日期，格式 `2026-11`。含义是：**这个日期我打开过，链接有效，内容范围没变。**

| 资源类型 | 建议复核周期 |
| --- | --- |
| 政策法规类 | 每季度 |
| 数据与统计类 | 每半年 |
| 课程与教材 | 每年 |
| 开源项目 | 每季度看一次活跃度 |
| 基础概念类 | 两年一次即可 |

仓库里有 `scripts/check_links.py`，跑一次能查出所有失效链接。

## 七、三条纪律

1. **能自动验证的先自动验证。** 代码跑一遍，链接点一次，数字核一遍。不能自动验证的，标明"未核实"。
2. **降级使用比升级使用安全。** 拿不准是几手，就按低一级用。
3. **标核验日期。** 没有日期的推荐等于没有推荐，因为你不知道它是什么时候还有效。
